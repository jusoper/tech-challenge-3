Tech Challenge — Fase 3
Entrega obrigatória: Repositório GitHub + Vídeo de 5 minutos (método STAR).
Atividade em grupo · Obrigatória · Avaliada (vale 90% da nota de todas as disciplinas da fase).

Tema Central: Deploy de Modelo em Produção com Pipeline CI/CD, Monitoramento e Otimização de Latência
Contexto: Um hospital de referência precisa de um sistema de triagem automática de exames de texto (laudos médicos) para classificar urgência (ex.: normal / atenção / urgente). O modelo central é um classificador de texto (NLP) leve, servido via API REST em container Docker, com pipeline CI/CD (GitHub Actions), orquestração de retreino (Airflow), monitoramento (Prometheus + Grafana) e otimizações de latência.

Requisitos Obrigatórios:
Repositório GitHub:
• Pipeline CI/CD básico com GitHub Actions (ex.: lint → test → build).
• Script ou DAG Airflow simples para pipeline de treino/retreino.
• Dockerfile funcional para o serviço de inferência.
• Stack de monitoramento local: API + Prometheus + Grafana via Docker Compose.
• Histórico de commits semântico e organizado.
  — Orientação do grupo: commitar ao concluir cada tarefa (ou bloco coerente), com mensagem objetiva (chore / docs / feat / refactor / test); evitar fechar a etapa inteira em um único commit.

Vídeo (5 minutos — método STAR):
• Situation: Problema clínico e importância da triagem rápida.
• Task: Requisitos técnicos da fase (latência, CI/CD, monitoramento).
• Action: Arquitetura escolhida, como o modelo foi otimizado e como a monitoração foi configurada.
• Result: Demonstração do pipeline funcionando, latência alcançada e lições aprendidas.

Bibliotecas Requeridas:
• Scikit-Learn (ou framework de preferência) — classificação de texto (ex.: TF-IDF + Random Forest).
• FastAPI — API de inferência.
• Prometheus-client — instrumentação de métricas.
• Airflow — orquestração de tarefas.

Boas Práticas Obrigatórias:
• CI/CD com ≥ 2 automações (ex.: lint + testes).
• DAG Airflow funcional (ex.: carregamento → treino → salvamento do modelo).
• Dashboard Grafana com ≥ 3 painéis (requisições, latência, taxa de erro).
• ≥ 1 técnica de otimização de latência (ONNX, quantização ou pruning).

Dataset Sugerido:
Classificação de textos médicos/triagem com ≥ 2.000 amostras.
Exemplos: Medical Abstracts TC Corpus (Kaggle), recortes MIMIC-III, ou tabular texto + target de urgência.

---

Etapas de Desenvolvimento (4 Etapas)

Etapa 1 — Decisão Arquitetural e API Inicial (Disciplina 01 — Deploy em Nuvem)
Foco: Decisão de arquitetura de deploy e setup da aplicação.
Tarefas e Referência
1. Analisar estratégia de deploy em nuvem (AWS / Azure / GCP) para o cenário hospitalar (batch vs. real-time) e documentar no README. Deploy Nuvem, Aulas 01–05
2. Criar API FastAPI que recebe texto do laudo e retorna classificação de urgência. Deploy Nuvem, Aula 01–02
3. Empacotar a API em Dockerfile e medir baseline de latência local. Deploy Nuvem, Aulas 03–05
4. Incluir considerações de FinOps/segurança na decisão arquitetural. Deploy Nuvem, Aula 06
Entregável: API funcional em Docker + decisão arquitetural no README.

Etapa 2 — CI/CD e Pipeline Automatizado (Disciplinas 02 e 03 — CI/CD + Pipeline de Treino)
Foco: Automação básica do código e do modelo.
Tarefas e Referência
1. Workflow GitHub Actions no push: lint + pytest (≥ 2 automações). CI/CD, Aulas 01–03 / 05–06
2. Separar pipeline de treino em etapas claras (ingest → train → save). Pipeline ML, Aulas 01–03
3. Criar DAG Airflow com tasks de leitura de CSV, treino e salvamento do modelo. Pipeline ML, Aula 05 / CI/CD Aula 06
4. Garantir reprodutibilidade básica do treino (seeds, paths, artefato do modelo). Pipeline ML, Aula 06–07
Entregável: Workflow YAML no repositório + arquivo .py da DAG Airflow.

Etapa 3 — Monitoramento e Observabilidade (Disciplinas 04 e 05 — Performance + Serviços)
Foco: Stack de observabilidade para a API.
Tarefas e Referência
1. Instrumentar a API com prometheus_client (latência de request + contagem de chamadas). Serviços Monitoração, Aulas 01–02
2. docker-compose.yml subindo API + Prometheus + Grafana juntos. Serviços Monitoração, Aulas 02–04
3. Dashboard Grafana com ≥ 3 painéis (requisições, latência, erros). Serviços Monitoração, Aula 03
4. Relacionar monitoramento com latência vs. throughput do serviço. Monitoração Performance, Aulas 01 / 05 / 08
Entregável: Compose da stack completa + print/JSON do dashboard.

Etapa 4 — Otimização de Latência e Entrega (Disciplina 06 — Latência em Dados Não Estruturados)
Foco: Modelo otimizado para inferência e consolidação.
Tarefas e Referência
1. Treinar classificador de texto (ex.: TF-IDF + Random Forest / modelo leve). Latência NLP, Aulas 01–02
2. Aplicar ≥ 1 otimização: ONNX Runtime, quantização ou pruning. Latência, Aula 04
3. Comparar latência do modelo original vs. otimizado (métrica documentada). Latência, Aulas 01 / 04
4. Finalizar README com arquitetura, setup e resultados de latência. —
5. Gravar vídeo STAR de 5 minutos. —
Entregável: Modelo otimizado + comparação de latência + link do vídeo.

Critérios de Avaliação
- Modelagem e Otimização — peso 20%: NLP funcional, otimização (ex.: ONNX) e melhoria de latência demonstrada.
- CI/CD (GitHub Actions) — peso 15%: Workflow configurado e rodando testes básicos.
- Orquestração (Airflow) — peso 15%: DAG funcional (ingestão + treino).
- Monitoramento — peso 20%: Compose funcional (API + Prometheus + Grafana) com dashboard.
- Documentação (README) — peso 15%: Arquitetura em nuvem escolhida + instruções claras de execução.
- Vídeo STAR — peso 15%: Clareza na demonstração técnica e impacto (≤ 5 min).

Passo a Passo Resumido

• [Etapa 3] Docker Compose com Prometheus + Grafana + dashboard.
• [Etapa 4] Otimização (ex.: ONNX) + comparação de latência + vídeo STAR.
